## 1. Executive Summary

This report establishes the claim-by-claim verification of the **EVay Lanka** intelligent Electric Vehicle (EV) routing, energy prediction, and charging reservation platform against the research presentation and submitted manuscript for **ICACT 2026**.

Following an exhaustive audit of production source code, unit test suites, simulation models, and telemetry datasets:
- **Cost Function Weights:** The production code (`smart_route_service.dart`), test assertions (`algorithm_verification_test.dart`), and IEEE validation report (`IEEE_RESEARCH_MANUSCRIPT_VALIDATION.md`) are verified to use $\alpha=0.35$ (distance), $\beta=0.45$ (energy), and $\gamma=0.20$ (delay). The discrepancy noted in earlier reports originated from legacy draft documentation (`ALGORITHM_VERIFICATION_AND_WORKED_EXAMPLES.md`), which has now been aligned.
- **Safety Boundary Enforcement:** Hard battery reserve enforcement at $10\%$ SoC ($5.03\text{ kWh}$) is mathematically verified at both model and service layers (`SmartRoute.canInitiateNavigation`, `SmartRouteService.validateNavigationReadiness`).
- **Empirical Scenarios:** All 45 method-scenario evaluations across 5 representative Sri Lankan corridors (C1–C5) and 3 initial battery levels ($30\%, 50\%, 80\%$) have been reproduced and validated.
- **Data Provenance:** The 8 OBD diagnostic traces in `data/telemetry/` are confirmed as physics-calibrated synthetic reference drive cycles generated by `tool/export_obd_traces.dart`. No false claims of direct physical OBD scanner logging exist.

## 3. Discrepancy Analysis & Remediation Log

### Discrepancy DIS-01: Cost Function Coefficient Documentation Mismatch
* **Presentation Claim:** $\alpha = 0.35$ (Distance), $\beta = 0.45$ (Energy), $\gamma = 0.20$ (Charging Delay).
* **Previous Handoff Report & Draft Docs:** $\alpha = 0.40, \beta = 0.35, \gamma = 0.25$.
* **Actual Code Implementation (`smart_route_service.dart#L260-L262`):**
  ```dart
  static const double alpha = 0.35; // Normalized detour weight
  static const double beta = 0.45;  // Normalized power & energy weight
  static const double gamma = 0.20; // Normalized slot/queue weight
  ```
* **Test Suite Verification (`algorithm_verification_test.dart#L20-L24`):**
  ```dart
  expect(SmartRouteService.alpha, equals(0.35));
  expect(SmartRouteService.beta, equals(0.45));
  expect(SmartRouteService.gamma, equals(0.20));
  ```
* **Root Cause:** Early preliminary exploratory commits used 0.40 / 0.35 / 0.25 before physical tuning emphasized energy consumption over raw distance for mountainous Sri Lankan terrain. `ALGORITHM_VERIFICATION_AND_WORKED_EXAMPLES.md` and `IMPROVEMENTS_BRANCH_DOCUMENTATION.md` retained draft text.
* **Remediation Executed:** Recomputed Worked Example 1 in `docs/ALGORITHM_VERIFICATION_AND_WORKED_EXAMPLES.md` and updated `docs/IMPROVEMENTS_BRANCH_DOCUMENTATION.md`. **No changes were made to production code**, as the code already accurately reflects the authoritative configuration and presentation.

### Discrepancy DIS-02: Scoping of Booking Concurrency Claims
* **Risk:** The 50-user concurrency benchmark could be misconstrued as live Google Cloud Firestore network latency measurement under inter-region network partitions.
* **Remediation Status:** Verified that both the test suite (`stage4_reliability_and_booking_concurrency_test.dart#L13-L62`) and manuscript (`IEEE_RESEARCH_MANUSCRIPT_VALIDATION.md#L54`) explicitly state this evaluates `InMemoryReservationEngine` (in-memory optimistic concurrency control) to assess application isolation logic, not remote cloud network latency.
